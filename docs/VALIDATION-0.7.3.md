## 名称与发布身份

显示名称为 **Deepseedian**；manifest ID、安装目录、内部视图、桥接协议、环境变量和 CSS 标识统一为 `deepseedian`。源码工作区所在文件夹不决定发布身份，无需搬动现有 Git checkout。

旧字符串仅在兼容读取与历史说明中保留。删除兼容代码中的旧字符串会使程序无法识别旧安装、旧记忆及旧导航。历史对话和用户正文按原字节保留，不对个人内容全局替换。

已发布 0.7.2 的安装目录仍是 `.obsidian/plugins/deepsidian/`，新源码构建安装在 `.obsidian/plugins/deepseedian/`。新旧 manifest 不得混装。Obsidian 要求本地插件 ID 与目录名一致，见[官方 Manifest 文档](https://docs.obsidian.md/Reference/Manifest)。

## 旧用户迁移

1. 先禁用旧插件，关闭 Obsidian，备份旧插件目录。不要仅重命名旧目录，也不要同时启用两版。
2. 将新构建的 `main.js`、`manifest.json`、`styles.css` 放到新 ID 目录，保留旧目录。
3. 重开 Obsidian，在第三方插件中启用 Deepseedian。新插件在读取设置前自动导入旧数据。
4. 核对历史会话、图片、记忆、记忆规则及开关，再继续使用。原快捷键绑定和旧侧栏布局不自动改写；需要重新打开侧栏、重新绑定快捷键。

导入包括 `data.json`、`memory/`、两个运行时中的 `sessions/`、`attachments/` 和匿名运行时标识。桥接代码、运行配置与旧补丁重新生成；不复制旧可执行插件。旧目录和迁移暂存快照保留。记忆与目录旧标记兼容读取，下一次正常写入时使用新标记。

新目录已有独立数据、旧插件仍启用、记忆仍有写锁、暂存/来源已改变或路径含符号链接时，迁移停止并提示，不覆盖两份数据。中断后相同快照可续传。原子发布使用文件系统硬链接；不支持此能力的文件系统会安全失败，需要维护者在关闭 Obsidian 并备份后人工迁移。

备份包含历史会话、附件和记忆，不应上传仓库。新版执行“忘记”不会清除旧目录或恢复快照。macOS 上保存的绝对 Node/DSH 路径在 Windows 上可能需要重新选择，迁移不会擅自猜测替换。

## 维护者实机验收（约 10 分钟）

1. **启动与名称**：重启 Obsidian → 设置 → 第三方插件，启用 Deepseedian。打开侧栏，检查自动连接和模型列表。安装目录应为 `deepseedian`，manifest 应为 0.7.3；第一次使用按连接引导检测 Node/DSH。
2. **选区提问**：新建临时笔记，写下“缓存可以加快重复读取，因为它避免访问较慢的存储层。”选中其中一句，用右键或命令面板中的“Deepseedian：围绕选区或当前段落提问”。应附上对应选区，不自动发送；发送后检查回答和来源跳转。
3. **手动补全**：设置中开启手动补全，在临时笔记写“缓存可以加快重复读取，因为它能”，光标放末尾。命令面板执行“请求当前位置补全”，灰字出现后 Tab 接受、Ctrl+Z 撤销。再请求一次，用 Esc 取消；取消不应写入正文。测试后可关闭手动补全。
4. **历史与分支**：让 AI 记住当前对话的实验代号 `CEDAR-7319`（强调仅限本对话，不写长期记忆）。从回答创建分支，确认标题编号不同；在父对话把代号改为 `MAPLE-8246`，分支仍应回答原代号。重启后历史搜索和分支续聊均应正常。
5. **记忆**：明确说“请记住：验收时我偏好先看一个短例子”，新会话确认能读到；随后明确要求忘记，在记忆管理窗口确认删除。新安装默认允许 AI 管理记忆，仍需会话读取和贡献权限；旧安装保留原开关。
